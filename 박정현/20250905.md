# 🦁 Today I Learned: Zustand vs Pinia

## 🔎 공통점 (Zustand & Pinia)
둘 다 **프론트엔드 상태 관리 라이브러리**로서, 전역 상태를 관리하고 컴포넌트 간 데이터를 공유하는 목적을 가집니다.

- **중앙 저장소(Store)**  
  상태와 로직을 한 곳에서 관리 → 여러 컴포넌트가 공유 가능  

- **직관적인 API**  
  Redux/Vuex 같은 복잡한 보일러플레이트를 줄이고 간단한 문법 제공  

- **선택적 구독**  
  필요한 상태만 가져와서 불필요한 렌더링 최소화  

- **상태와 액션 함께 정의**  
  store 안에 `state`와 `actions`를 같이 선언하여 응집력 높음  

---

## ⚙️ 차이점

| 항목 | Zustand (React) | Pinia (Vue) |
|------|-----------------|-------------|
| 프레임워크 | React 전용 | Vue 전용 |
| 사용 방식 | Hook(`useStore`)으로 상태 접근 | `useStore()` 함수로 상태 접근 |
| store 정의 | `create()` 함수 사용, JS 함수형 스타일 | `defineStore()` 함수 사용, Vue Options/Composition API 스타일 |
| 상태 관리 철학 | 매우 가벼운 미니멀리즘 | Vue 생태계에 맞춘 공식 차세대 상태 관리 |
| 리액티브 방식 | React의 state 시스템 기반 | Vue의 reactivity 시스템 기반 (ref, reactive) |
| 미들웨어/확장 | `persist`, `devtools` 등 선택적으로 붙임 | Vue Devtools, Pinia Plugin 생태계 풍부 |
| 코드 스타일 | 함수형, 자유도 높음 → 개발자 마음대로 설계 가능 | Vue 문법과 유사 → 일관된 구조 제공 |

---

## 💡 요약
- **같은 점**: 전역 상태를 효율적으로 관리, 단순한 API, 선택적 구독, 상태+액션 함께 정의  
- **다른 점**:  
  - **Zustand**는 React 환경에 최적화된 초경량 라이브러리 → 자유도가 높고 심플  
  - **Pinia**는 Vue 공식 상태 관리 솔루션 → Vue의 반응성 시스템과 자연스럽게 통합  

---

## ✨ 오늘 배운 포인트
- Zustand와 Pinia는 **역할은 같다** → "상태 관리 저장소"  
- **React 쓰면 Zustand, Vue 쓰면 Pinia**라는 차이일 뿐, 개념은 거의 동일하다.  
- 다만 **Zustand는 더 자유롭고 가볍고**, **Pinia는 Vue와 강하게 결합되어 안정적**이라는 느낌으로 이해하면 된다.
