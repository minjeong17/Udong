# MCP (Model Context Protocol)

## MCP란?
MCP는 **LLM(대규모 언어 모델) 클라이언트가 외부 서비스/도구를 안전하고 표준화된 방식으로 사용**하게 해주는 프로토콜입니다.  
모델이 “어떤 기능(툴)이 있고, 어떻게 호출하는지”를 **발견 → 권한 확인 → 호출 → 결과 수신**의 흐름으로 수행합니다.

---

## 🔎 핵심 개념
- **Client**  
  LLM이 실행되는 쪽. 예: 대화형 앱, 에이전트 런타임.
- **Server**  
  툴을 실제로 제공하는 제공자. 파일, 캘린더, Notion/Jira, 사내 API 등.
- **Tool**  
  외부 기능 단위. 이름/입력 스키마/출력 스키마가 정의됨.
- **Resource**  
  읽기 중심의 데이터 소스(예: 파일, 문서, DB 레코드)를 노출.
- **Prompt**  
  서버가 제공하는 프롬프트 템플릿(옵션).
- **Transport & Session**  
  stdio/WebSocket 등 전송 방식과 세션(권한, 기능 목록, 이벤트) 관리.

---

## ⚙️ 주요 구성 요소
- **Capabilities(기능 광고)**: 서버가 제공 가능한 `tools/resources/prompts`를 클라이언트에 알림  
- **Schema 기반 I/O**: 각 툴은 **JSON Schema**로 파라미터/응답을 명시  
- **권한/안전성**: 클라이언트가 툴 호출 전 사용자 동의를 요구하거나 스코프를 제한  
- **이벤트/스트리밍(선택)**: 진행 상황이나 부분 결과를 스트림으로 전달 가능  
- **클라이언트 통합**: (예) 데스크톱 앱/에이전트 런타임이 MCP 서버들을 등록하여 사용

---

## 🔄 동작 흐름
1. **연결**: Client ↔ Server 세션 수립  
2. **발견**: Server가 지원 툴·리소스를 목록으로 광고  
3. **기획**: 모델이 사용자 의도에 맞춰 호출할 툴을 선택  
4. **권한**: 필요 시 사용자 승인(예: “Notion에 페이지 생성 허용?”)  
5. **호출**: 입력 스키마에 맞춰 Tool 실행  
6. **결과**: Tool 응답을 모델 답변 생성에 반영(필요 시 후속 호출 반복)

---

## 🧩 예시 (파일 요약 → Notion 기록)
- **구성**
  - Tool A: `fs.read(path)` — 로컬/원격 파일을 읽어 텍스트 제공
  - Tool B: `notion.createPage(databaseId, title, content)` — Notion 페이지 생성
  - (옵션) Resource: `fs://meeting-notes/2025-09-03.md`

- **흐름**
사용자: “회의록 파일 요약하고 Notion에 기록해줘.”  
↓  
Client: `fs.read` 호출로 텍스트 확보  
↓  
LLM: 요약 생성  
↓  
Client: `notion.createPage` 호출로 결과 업로드  
↓  
사용자에게 Notion 링크 반환

---

## 🛠️ 프로젝트 적용 시나리오 (🎤 음성 → 📄 요약 → 📓 Notion/Jira 기록)
1. **STT 서버(또는 외부 STT API) → MCP Tool**  
   - `stt.transcribe(audioPath)` → 텍스트
2. **정리 체인(모델 내부 프롬프트) + MCP Tool**  
   - 액션 아이템/담당자/마감일 추출
3. **업무 시스템 연동 Tool**  
   - `notion.createPage`, `jira.createIssue`, `calendar.createEvent`
4. **메모리/컨텍스트**  
   - 지난 회의 리소스를 `resource`로 노출하여 연속 맥락 유지

> 장점: STT/Notion/Jira/캘린더 등 **각 기능을 독립 서버(툴 제공자)로 나누어 유지보수**가 쉬움.  
> 다양한 클라이언트(데스크톱 앱, 다른 에이전트 런타임)에서 **같은 MCP 서버 재사용** 가능.

## ✅ LangChain과 비교
| 항목 | MCP | LangChain |
|---|---|---|
| 역할 | **모델 ↔ 외부 도구 연결 표준(프로토콜)** | **LLM 앱 프레임워크(체인/에이전트 조립)** |
| 초점 | 안전한 툴 노출, 권한, I/O 스키마, 재사용성 | 워크플로 구성, 리트리벌/체인/에이전트 추상화 |
| 서버/도구 | 독립 서버가 툴을 제공(모듈화) | 코드 내부에서 툴/체인을 조립 |
| 클라이언트 | MCP 호환 런타임(대화 앱/에이전트 런타임 등) | Python/JS SDK 중심 실행 |
| 강점 | 재사용·안전·표준 인터페이스 | 빠른 개발·리트리벌/체인 생태계 |
| 적합도 | 사내/외부 시스템을 **표준화해 여러 클라이언트가 공유** | 한 앱 내부에서 **빠르게 체인/에이전트 구성** |

> 결론: **외부 시스템을 표준 인터페이스로 묶어 두고 여러 앱에서 쓰려면 MCP**,  
> **한 프로젝트 안에서 체인을 빠르게 조립·실험하려면 LangChain**이 유리.

## 🚀 빠른 스타트(개념 예시)
> 실제 SDK/런타임별 설정은 다를 수 있으니 구조만 참고용으로 제시

### 1) 서버(툴 제공자) 개념 코드
```ts
// server.ts (개념 예시)
import { createServer, defineTool } from "mcp-server"; // 가상의 API

const sum = defineTool({
  name: "math.sum",
  description: "두 수의 합을 구함",
  inputSchema: { type: "object", properties: { a: {type:"number"}, b: {type:"number"} }, required:["a","b"] },
  handler: async ({ a, b }) => ({ result: a + b }),
});

createServer({
  tools: [sum],
  resources: [{ uri: "fs://notes/weekly.md", description: "주간 회의록" }],
}).listen({ stdio: true });
```

### 2) 클라이언트 등록(개념)
```json
{
  "servers": [
    {
      "name": "local-tools",
      "command": "node",
      "args": ["server.js"],
      "transport": "stdio",
      "allowedTools": ["math.*", "notion.*"]
    }
  ]
}
```

### 3) 호출 흐름(대화 예)
```
사용자: "a=3, b=5 합 좀 구해줘"
→ Client가 math.sum 툴 후보로 선택
→ 사용자 승인/자동 정책 확인
→ { "tool":"math.sum", "input": {"a":3,"b":5} } 호출
← { "result": 8 } 수신
→ 모델이 최종 답변 생성
```

## ✅ 정리
- MCP는 **외부 기능을 표준화된 “툴”로 안전하게 노출**하여 LLM이 사용할 수 있게 하는 프로토콜  
- 도구 재사용·보안·경계 구분에 강점  
- LangChain과 함께 쓰면:  
  - **MCP**로 사내/외부 리소스와 액션을 통합 노출  
  - **LangChain**으로 앱 내부 체인(요약/리트리벌/후처리) 구성 → **최종 호출은 MCP 툴**  
- “음성→요약→Notion/Jira 기록” 파이프라인에 적합하며, 기능을 서버 단위로 나눠 **모듈형 확장**이 가능함.
