# Model Context Protocol (MCP)

## 📌 MCP란?
MCP(Model Context Protocol)는 **AI 모델이 외부 도구·서비스와 안전하고 확장성 있게 연결되도록 하는 표준 프로토콜**입니다.  
쉽게 말해, **AI 친화적인 API 래퍼 표준**이라고 할 수 있습니다.

---

## 🔎 핵심 개념
- **표준화된 인터페이스**  
  모델이 다양한 서비스(API, DB, SaaS 등)와 연결될 때, MCP라는 공통 규격만 이해하면 됨.
  
- **모델 친화적 설계**  
  복잡한 REST API나 SDK 대신, **모델이 쉽게 호출 가능한 툴(Tool)과 리소스(Resource)** 형태로 제공.

- **보안과 권한 제어**  
  사용자가 허용한 서버만 접근 가능. 모델이 임의로 인터넷 전체를 탐색하지 않음.

---

## ⚙️ 주요 구성 요소
- **MCP 서버(Server)**  
  실제 기능과 데이터를 제공하는 쪽.  
  예: Notion 서버, Jira 서버, 사내 DB 서버, STT 서버 등.

- **MCP 클라이언트(Client)**  
  MCP 서버와 모델을 연결해주는 중간 계층.  
  예: Claude Desktop, 혹은 우리가 직접 만든 백엔드 클라이언트.

- **툴(Tools)**  
  실행 가능한 기능(API 메서드).  
  예: `transcribe_audio`, `create_page`, `search_listings`

- **리소스(Resources)**  
  조회/읽기 전용 데이터.  
  예: 특정 문서, 파일, 티켓 목록 등.

---

## 🔄 동작 흐름
1. **MCP 클라이언트 실행**  
   - 등록된 MCP 서버를 자동으로 탐색.

2. **서버 → 툴/리소스 목록 전달**  
   - `list_tools`, `list_resources` API로 모델에게 가능한 기능을 알려줌.

3. **모델 판단 & 툴 호출**  
   - 사용자의 프롬프트를 이해하고, 어떤 MCP 툴을 호출할지 스스로 결정.  
   - 필요 시 사용자에게 확인을 요청.

4. **결과 반환**  
   - 툴 실행 결과를 모델이 받아, 사용자에게 자연어로 응답.

---

## 🧩 예시 (Airbnb API → MCP 툴화)
- **원본 API**
GET /listings?city=Seoul&date=2025-09-02
→ 인증, 파라미터, 응답 파싱 필요 (개발자 중심)

- **MCP 툴 정의**
```json
{
  "name": "airbnb.search_listings",
  "description": "도시와 날짜 기준으로 숙소 검색",
  "inputSchema": {
    "type": "object",
    "properties": {
      "city": { "type": "string" },
      "date": { "type": "string", "format": "date" }
    },
    "required": ["city", "date"]
  }
}
