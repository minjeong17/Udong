## 여행 루트 최적화 방법

### 1. 취향 이해

- 목표: 사용자의 말(자연어)을 기계가 계산 가능한 값으로 바꾸기
- 입력: 날짜/도시/인원/이동수단/선호(카페·맛집…)/걷기 허용/점심·저녁 시간/예약
- 하는 일
    - 선호를 0~1 가중치 벡터로 변환(카페 0.8, 자연 0.4 같은 느낌)
    - 제약 파라미터 산출(하루 걷기 한도, 식사 시간창, 휴식 시간, 반드시 가야 할 곳)
- 결과: 선호 가중치 + 제약 파라미터 세트

### 2. 후보 모으기

- 목표: 명소/식당/숙소/항공의 "기본 정보" 확보
- 입력: 도시/날짜/선호 카테고리/예산 대역
- 하는 일
    - 공식 API로 위치·평점·리뷰수·영업시간·편의 수집
    - 방문 예상 **체류시간(서비스타임)**을 카테고리별로 30/60/90분 등급화
    - (정책) 가격·재고·결제는 링크아웃, 우리는 “추천 카드”까지만
- 결과: 정리된 후보 풀(명소/식당/숙소/항공)

### 3. 추천 랭킹

- 목표: 후보를 “우리 여행에 맞는 순서”로 세우기
- 입력: 후보 풀 + 선호 가중치 + (임시) 이동시간 근사
- 하는 일
    - 선호 적합도(카테고리↔가중치), 접근성(이동시간), 리뷰 신뢰도, 시간창 적합성을 점수로 합산
    - 상위 N개만 컷오프하여 과밀 방지
- 결과: 숙소/명소/식당/항공의 TOP 리스트

### 4. 날짜 배분

- 목표: 일수만큼 “하루치 묶음” 만들기
- 입력: TOP 후보 + 날짜 수 + 예약/영업시간
- 하는 일
    - 가까운 장소끼리 지리적으로 묶고, 오픈·예약 시간을 고려해 날짜 배치
    - 하루 **총 시간(체류+이동)**이 한도를 넘지 않게 조정
- 결과: 날짜별 후보 묶음(데이 팩)

### 5. 동선 최적화

- 목표: 하루 방문 순서·도착시간 자동 정렬(이동 최소 + 시간창 준수)
- 입력: 날짜별 후보 묶음 + 이동시간 행렬(경로 API) + 제약 파라미터
- 하는 일
    - 최적화 엔진(OR-Tools/Mapbox)로 시간창·체류·휴식·시작/종료 제약을 지키며 해 탐색
    - 선택 방문은 무리면 자동 탈락(페널티로 제어)
- 결과: 하루 타임라인(도착/출발/체류/다음 ETA)

### 6. 설명·대안 생성

- 목표: 사람이 이해하기 쉬운 이유 설명과 플랜 B 제공
- 입력: 완성된 타임라인 + 후보 대체지
- 하는 일
    - "영업시간/이동 최소/예약 맞춤" 기반 선택 근거 문장화
    - 비·휴무·혼잡 시 대체 코스/역순 제안
- 결과: 설명 카드 + 플랜 B 카드

### 7. 산출물 구성

- 목표: 공유·사용 가능한 최종 결과물 만들기
- 입력: 타임라인/설명/추천 카드
- 하는 일
    - 지도 경로(폴리라인), 타임라인, 상위 추천 카드(숙소·식당·항공) 정리
    - PDF/캘린더(ICS)/지도·내비 링크/공유 링크 생성
- 결과: 사용자가 바로 쓰는 완성본 패키지

### 8. 운영 기본 원칙(한 줄씩)

- 공식 API 우선, 크롤링 지양 / 가격·재고·결제는 링크아웃
- 이동시간 캐싱으로 비용 절감 / 실패 시 간단 정렬→로컬 개선 폴백
- 기본 여유 버퍼 삽입, 과도한 이동/연속 걷기 경고 및 수정 제안
