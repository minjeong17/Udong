# 2025년 9월 1일 학습 내용 (TIL)

## 인프라 학습: EC2와 MobaXterm

어제는 AWS의 핵심 서비스인 EC2와 원격 접속 클라이언트인 MobaXterm에 대해 학습했습니다.

### 1\. Amazon EC2 (Elastic Compute Cloud)

EC2는 AWS에서 제공하는 가상 서버로, 클라우드 환경에서 컴퓨팅 파워를 필요에 따라 조절하며 사용할 수 있는 서비스입니다.

- **주요 개념**:

  - **인스턴스(Instance)**: AWS 클라우드에서 실행되는 가상 서버입니다. EC2의 가장 기본적인 구성 요소입니다.
  - **AMI (Amazon Machine Image)**: 인스턴스를 생성하는 데 사용되는 템플릿입니다. 운영체제(OS) 및 필요한 소프트웨어가 미리 구성되어 있습니다.
  - **인스턴스 유형(Instance Types)**: 다양한 CPU, 메모리, 스토리지, 네트워크 사양의 조합으로 제공됩니다. 사용자는 워크로드에 가장 적합한 유형을 선택할 수 있습니다. (예: AWS 프리티어로 사용 가능한 `t2.micro`)
  - **보안 그룹(Security Groups)**: 인스턴스에 대한 인바운드/아웃바운드 트래픽을 제어하는 가상 방화벽 역할을 합니다. 특정 IP와 포트에 대한 접근을 허용/차단하는 규칙을 설정할 수 있습니다.

- **핵심 특징**:

  - **탄력성 및 확장성 (Scalability)**: 몇 분 만에 컴퓨팅 용량을 늘리거나 줄일 수 있어, 트래픽 변화에 유연하게 대응할 수 있습니다.
  - **사용한 만큼만 지불 (Pay-as-you-go)**: 실제 사용한 만큼만 비용을 지불하므로 초기 하드웨어 투자 비용 없이 경제적으로 이용할 수 있습니다.

### 2\. MobaXterm

MobaXterm은 Windows 환경에서 원격 서버에 접속하고 관리하는 작업을 도와주는 올인원(All-in-One) 터미널 프로그램입니다.

- **주요 기능**:
  - **통합 원격 접속**: SSH, RDP, VNC, FTP 등 다양한 프로토콜을 하나의 프로그램에서 모두 지원합니다.
  - **탭 기반 터미널**: 여러 개의 터미널 세션을 탭으로 관리하여 동시에 여러 서버 작업을 편리하게 수행할 수 있습니다.
  - **세션 관리**: 자주 접속하는 서버 정보를 저장해두고 사이드바에서 클릭 한 번으로 쉽게 재접속할 수 있습니다.
  - **그래픽 SFTP 브라우저**: SSH로 원격 서버에 접속하면, 자동으로 그래픽 파일 탐색기가 열려 로컬 PC와 서버 간에 파일을 드래그 앤 드롭으로 쉽게 주고받을 수 있습니다.
  - **내장 X11 서버**: 별도의 설정 없이도 원격 리눅스/유닉스 서버의 GUI 애플리케이션을 Windows 데스크톱으로 전달받아 실행할 수 있습니다.
  - **휴대성 (Portable)**: 설치 없이 USB 드라이브 등에서 바로 실행할 수 있는 포터블 버전을 제공합니다.

# 2025년 9월 2일 학습 내용 (TIL)

## 인프라 학습: Jenkins와 Grafana

오늘은 CI/CD 자동화 도구인 젠킨스와 데이터 시각화 도구인 그라파나에 대해 학습했습니다.

### 1\. Jenkins (젠킨스)

젠킨스는 소프트웨어 개발 프로세스 중 빌드, 테스트, 배포 단계를 자동화하여 **CI/CD (지속적 통합/지속적 제공)** 환경을 구축하기 위한 오픈소스 자동화 서버입니다.

- **주요 특징**:
  - **CI/CD 자동화**: 코드 변경 사항을 정기적으로 통합하고, 빌드 및 테스트를 자동으로 수행하여 개발 주기를 단축하고 버그를 조기에 발견할 수 있도록 돕습니다.
  - **방대한 플러그인 생태계**: 1,800개 이상의 플러그인을 통해 Git, Maven, Docker, AWS 등 거의 모든 개발 도구 및 클라우드 서비스와 유연하게 연동할 수 있습니다.
  - **파이프라인(Pipeline as Code)**: `Jenkinsfile`이라는 텍스트 파일을 사용하여 전체 빌드, 테스트, 배포 워크플로우를 코드로 정의할 수 있습니다. 이를 통해 CI/CD 프로세스를 버전 관리하고, 검토하며, 재사용하기 용이합니다.
  - **분산 빌드**: 여러 대의 컴퓨터(Agent)에 빌드 및 테스트 작업을 분산시켜 대규모 프로젝트의 처리 속도를 높일 수 있습니다.
  - **오픈소스**: 누구나 무료로 사용할 수 있으며, 거대한 커뮤니티를 통해 풍부한 문서와 지원을 받을 수 있습니다.

### 2\. Grafana (그라파나)

그라파나는 다양한 데이터 소스로부터 얻은 메트릭(수치 데이터)을 수집하여, 사용자가 이해하기 쉬운 대시보드로 시각화하고 모니터링할 수 있게 해주는 오픈소스 플랫폼입니다.

- **주요 특징**:
  - **통합 대시보드**: Prometheus, InfluxDB, AWS CloudWatch, MySQL 등 여러 곳에 흩어져 있는 데이터 소스를 하나로 연결하여 통합된 대시보드를 만들 수 있습니다.
  - **다양한 시각화 옵션**: 차트, 그래프, 테이블, 히트맵 등 풍부한 시각화 패널을 제공하여 복잡한 데이터를 직관적으로 표현할 수 있습니다.
  - **유연한 맞춤 설정**: 드래그 앤 드롭 인터페이스를 통해 사용자가 원하는 대로 대시보드를 쉽게 구성하고 편집할 수 있습니다.
  - **알림 시스템**: 특정 메트릭이 미리 정의된 임계값을 넘었을 때, Slack, 이메일, PagerDuty 등 다양한 채널을 통해 실시간으로 알림을 받을 수 있습니다.
  - **어노테이션(Annotations)**: 그래프 위에 직접 메모나 이벤트를 기록하여 특정 시점의 이슈나 변경 사항을 쉽게 파악하고 공유할 수 있습니다.

# 2025년 9월 3일 학습 내용 (TIL)

## DB 설계 및 반정규화

### 1\. 적절한 데이터 타입 선택

- 데이터 유형은 일반적으로 문자형, 숫자형, 날짜형으로 구분됩니다.
- 저장할 데이터에 비해 과하지 않은 데이터 타입을 설정해야 용량 낭비를 줄일 수 있습니다.
- 일반적으로 데이터를 저장하는 데 문제가 없는 타입 중 **가장 작은 것을 선택**하는 것이 좋습니다.
  - 작은 데이터 타입일수록 디스크나 메모리에 더 적은 공간을 사용하므로 성능이 향상됩니다.

### 2\. DB 정규화의 특징

- 테이블 간의 중복 데이터를 최소화합니다.
- 저장 용량을 최적화하고 데이터 무결성을 유지하는 데 도움이 됩니다.
- 쿼리에서 `JOIN`을 많이 사용하게 되어 응답 시간이 저하될 수 있습니다.

### 3\. DB 반정규화란?

- 시스템 성능 향상, 개발 과정의 편의성, 운영의 단순화를 위해 **의도적으로 정규화 원칙을 위배**하는 과정입니다.
- **정규화 이후에 수행**하는 것이 원칙입니다.

### 4\. 반정규화 고려 대상

- 대량의 범위를 자주 처리해야 하는 경우
- 특정 범위의 데이터만 자주 처리하는 경우
- 요약/집계 정보가 자주 요구되는 경우
- `JOIN`으로 인한 성능 저하가 예상될 때

### 5\. 반정규화 기법

- 1:1 관계 테이블 병합
- 1:N 관계 테이블 병합
- 슈퍼/서브 타입 테이블 병합
- 수직 분할 (자주 사용하는 일부 컬럼을 분리)
- 수평 분할 (행으로 구분하여 구간별 분리)
- 테이블 추가 (중복, 통계, 이력, 부분 테이블)

---

## Index

### 1\. Index란?

- 책의 '색인'과 같은 개념으로, 테이블에서 원하는 데이터를 빠르게 찾기 위해 사용됩니다.
- 본문의 중요한 항목(컬럼)을 뽑아 따로 모아두고, 해당 데이터의 위치 정보를 저장합니다.

### 2\. Index 종류

- **Clustered Index (클러스터형 인덱스)**
  - 테이블당 1개만 생성 가능 (보통 PK 생성 시 자동 생성)
  - 인덱스로 지정한 열에 맞춰 행 데이터가 **자동으로 정렬**됩니다.
  - 리프 페이지가 곧 데이터 페이지이므로 Non-clustered Index보다 검색 속도가 빠릅니다.
- **Non-clustered Index (비클러스터형 인덱스)**
  - 테이블당 여러 개를 생성할 수 있습니다.
  - 필요에 의해 추가로 생성합니다.
  - 데이터 페이지를 직접 정렬하지 않고, 별도의 인덱스 페이지를 생성하여 데이터 위치에 대한 포인터를 가집니다.

### 3\. Index 내부 동작

- B-Tree (Balanced Tree) 구조를 사용하여 데이터를 효율적으로 탐색합니다.
- 데이터 삽입/삭제 시 페이지 분할이나 병합이 발생하여 구조를 재조정합니다.

### 4\. Index 장단점

- **장점**:
  - 검색 속도 향상
  - 전반적인 시스템 부하 감소
- **단점**:
  - 인덱스 관리를 위한 추가 저장 공간 필요
  - `INSERT`, `UPDATE`, `DELETE`와 같은 DML 작업 시 인덱스도 함께 수정해야 하므로 시간이 더 소요됨
  - 잦은 `UPDATE`, `DELETE`가 발생하는 컬럼에 인덱스를 잘못 사용하면 오히려 성능에 악영향을 줄 수 있음

### 5\. Index Hint

- Query Optimizer가 최적의 인덱스를 사용하지 않을 때, 개발자가 직접 사용할 인덱스를 지정하는 방법입니다.
- `USE INDEX`: 특정 인덱스 사용을 권장
- `FORCE INDEX`: 명시한 인덱스를 무조건 사용
- `IGNORE INDEX`: 특정 인덱스를 사용하지 않도록 함

# 2025년 9월 4일 학습 내용 (TIL)

## 무중단 배포 (Zero-Downtime Deployment)

무중단 배포는 **서비스를 중단하지 않고 새로운 버전을 배포**하는 기술입니다. 사용자는 애플리케이션이 업데이트되는 동안에도 서비스 중단을 경험하지 않으므로, 서비스의 가용성과 안정성을 높일 수 있습니다. 오늘은 여러 무중단 배포 전략 중 **블루/그린(Blue/Green)** 배포 방식에 대해 학습했습니다.

### 1\. 블루/그린 배포란?

블루/그린 배포는 **두 개의 동일한 운영 환경**을 구성하여 무중단 배포를 실현하는 전략입니다.

- **블루 (Blue)**: 현재 운영 중인 실제 서비스 환경 (Old Version)
- **그린 (Green)**: 새로 배포할 버전이 적용된 유휴 환경 (New Version)

기본 아이디어는 운영 중인 '블루' 환경과 똑같은 '그린' 환경을 미리 구축한 뒤, 새로운 버전을 '그린' 환경에 배포하는 것입니다. 배포가 완료되고 테스트를 통해 안정성이 확인되면, 라우터를 통해 모든 트래픽을 '블루'에서 '그린'으로 한 번에 전환합니다.

### 2\. 블루/그린 배포 절차

1.  **환경 복제**: 현재 운영 환경인 **블루**와 동일한 스펙의 **그린** 환경을 준비합니다.
2.  **신규 버전 배포**: 새로운 버전의 애플리케이션을 **그린** 환경에 배포합니다.
3.  **테스트**: 개발팀과 QA팀은 **그린** 환경에 접속하여 기능이 정상적으로 동작하는지 충분히 테스트합니다. 이 단계에서 실제 사용자 트래픽은 여전히 **블루** 환경으로 향하고 있습니다.
4.  **트래픽 전환**: **그린** 환경의 안정성이 검증되면 로드 밸런서(라우터)를 이용해 모든 트래픽을 **블루**에서 **그린**으로 즉시 전환합니다. 이제 **그린**이 새로운 운영 환경이 됩니다.
5.  **기존 환경 대기**: 구버전인 **블루** 환경은 트래픽을 받지 않는 상태로 일정 기간 대기시킵니다. 이는 혹시 모를 장애 발생 시 빠른 롤백(Rollback)을 위함입니다.
6.  **기존 환경 정리**: 새로운 버전이 안정적으로 운영되는 것이 확인되면, **블루** 환경을 다음 배포를 위한 유휴 자원으로 활용하거나 제거합니다.

### 3\. 블루/그린 배포의 장단점

#### 장점

- **빠른 롤백 (Fast Rollback)**: 배포된 새 버전에 심각한 문제가 발생하더라도, 라우터 설정만 변경하면 즉시 트래픽을 기존의 **블루** 환경으로 되돌릴 수 있어 장애 대응이 매우 빠르고 간단합니다.
- **안정적인 테스트 환경**: 실제 운영 환경과 동일한 **그린** 환경에서 충분한 테스트를 진행할 수 있어 배포 리스크를 크게 줄일 수 있습니다.
- **서비스 중단 없음**: 트래픽 전환이 순식간에 이루어지므로 사용자는 서비스 중단을 전혀 체감하지 못합니다.

#### 단점

- **자원 비용 문제**: 동일한 환경을 2세트 유지해야 하므로 서버, 데이터베이스 등의 인프라 비용이 두 배로 발생합니다.
- **데이터베이스 관리의 어려움**: 블루와 그린 환경이 운영되는 동안 데이터베이스 스키마 변경이나 데이터 정합성 문제가 발생할 수 있습니다. 이를 해결하기 위해 데이터베이스 호환성 유지를 위한 추가적인 설계가 필요합니다.
- **전환 시점의 일시적 과부하**: 트래픽이 한 번에 전환되면서 **그린** 환경의 인스턴스들이 갑작스러운 부하를 감당해야 할 수 있습니다. (Auto Scaling 등 예열 작업 필요)

## 코드형 인프라 (Infrastructure as Code, IaC)

오늘은 인프라를 코드로 관리하는 방식인 **IaC(Infrastructure as Code)** 와 이를 위한 강력한 도구 **테라폼(Terraform)** 에 대해 학습했습니다. DevOps 문화의 핵심적인 부분으로, 인프라 관리의 패러다임을 바꾸고 있습니다.

### 1\. IaC (Infrastructure as Code)란?

IaC는 **코드를 통해 인프라를 정의하고, 배포하며, 관리**하는 프로세스를 의미합니다. 기존에는 AWS, GCP 같은 클라우드 콘솔에 직접 접속하여 클릭으로 서버를 생성하거나, 수동으로 스크립트를 실행하여 환경을 구성했습니다. 이러한 방식은 실수가 잦고, 동일한 환경을 반복적으로 구성하기 어려웠습니다.

IaC는 이러한 문제점을 해결하기 위해 서버, 데이터베이스, 네트워크 등의 인프라 구성을 **버전 관리가 가능한 코드(정의 파일)** 로 작성합니다. 이를 통해 다음과 같은 이점을 얻을 수 있습니다.

- **자동화 및 속도**: 코드를 실행하기만 하면 인프라가 자동으로 구축되므로 배포 속도가 획기적으로 빨라집니다.
- **일관성 및 재현성**: 모든 인프라 구성이 코드로 명시되어 있어, 개발, 스테이징, 운영 환경을 항상 동일하게 유지할 수 있습니다.
- **가시성 및 추적성**: Git과 같은 버전 관리 시스템으로 인프라 변경 이력을 추적하고, 누가, 언제, 무엇을 변경했는지 쉽게 파악할 수 있습니다. (문서화 효과)
- **비용 절감**: 수동 작업에 필요한 인력을 줄이고, 사용하지 않는 인프라를 코드로 쉽게 제거하여 비용을 최적화할 수 있습니다.

### 2\. 테라폼 (Terraform) 이란?

테라폼은 **하시코프(HashiCorp)** 에서 개발한 대표적인 오픈소스 IaC 도구입니다. **HCL(HashiCorp Configuration Language)** 이라는 직관적인 언어를 사용하여 인프라의 **'최종 상태(Desired State)'** 를 선언적으로 정의합니다.

예를 들어, "EC2 인스턴스 5개를 생성하라"고 명령하는 것이 아니라, "EC2 인스턴스 5개가 존재하는 상태여야 한다"라고 코드에 선언하는 방식입니다. 그러면 테라폼이 현재 상태와 코드에 선언된 최종 상태를 비교하여, 변경이 필요한 부분을 자동으로 계획하고 적용해 줍니다.

### 3\. 테라폼의 핵심 워크플로우

테라폼은 주로 3가지 명령어를 통해 인프라를 관리합니다.

1.  **`terraform init`**: 작업 디렉터리를 초기화하는 단계입니다. 코드에 정의된 프로바이더(AWS, GCP 등) 플러그인을 다운로드하여 테라폼을 사용할 준비를 합니다.
2.  **`terraform plan`**: 작성된 코드를 현재 인프라 상태와 비교하여, 어떤 리소스가 생성, 수정, 또는 삭제될 것인지 **실행 계획**을 보여줍니다. 실제 인프라에 변경을 가하기 전에 예측할 수 있어 안전합니다.
3.  **`terraform apply`**: `plan` 단계에서 확인한 실행 계획을 실제로 인프라에 적용합니다. 이 명령을 실행하면 코드로 정의한 인프라가 생성되거나 변경됩니다.

### 4\. 테라폼의 장점

- **멀티 클라우드 지원**: 특정 클라우드 플랫폼에 종속되지 않고 AWS, GCP, Azure 등 다양한 클라우드 및 온프레미스 환경을 하나의 도구로 관리할 수 있습니다.
- **상태 관리 (State Management)**: 테라폼은 생성된 인프라의 상태를 `terraform.tfstate` 파일에 기록하여 관리합니다. 이를 통해 코드와 실제 인프라 간의 관계를 추적하고, 변경 사항을 정확하게 파악할 수 있습니다.
- **강력한 커뮤니티와 생태계**: 오픈소스로서 수많은 사용자와 방대한 모듈(재사용 가능한 코드 묶음)을 보유하고 있어 원하는 인프라를 쉽게 구성할 수 있습니다.
