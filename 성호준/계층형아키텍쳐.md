# 계층형 아키텍처 패턴(Layered Architecture Pattern)

## 개요
계층형 아키텍처 패턴(Layered Architecture Pattern)은 소프트웨어 시스템을 여러 개의 **독립적인 계층(layer)**으로 나누고, 각 계층마다 명확한 역할과 책임을 부여하는 구조 설계 방식입니다. 각 레이어는 바로 아래에 있는 레이어의 서비스만을 사용하며, 상위/하위 계층 간의 결합도를 낮춰 **유지보수성과 확장성**을 높입니다[web:38][web:39].

---

## 대표 계층 구조

일반적인 4계층 구조 예시:
- **Presentation Layer (UI Layer)**: 사용자와 직접 상호작용(입력/출력/뷰 처리)
- **Application Layer (Service Layer)**: 사용자 요청을 비즈니스 로직에 전달/조율
- **Business Logic Layer (Domain Layer)**: 핵심 도메인 규칙, 데이터 처리·비즈니스 연산 담당
- **Data Access Layer (Persistence Layer)**: 데이터베이스·외부 시스템과 연결 및 처리[web:38][web:41]

---

## 특징 및 장점

- **분리와 모듈화**: 계층별 책임이 분명하여 역할 분리 및 코드 관리 용이
- **유지보수 및 테스트 용이성**: 특정 계층만 수정해도 다른 계층에 미치는 영향 최소화
- **재사용성 향상**: 동일한 비즈니스 로직이나 데이터 접근 코드를 여러 곳에서 재사용 가능
- **표준화/이식성**: 각 계층 인터페이스만 고정하면 내부 구현은 언제든 교체 가능
- **보안 강화**: 외부 접근 제한 및 데이터 검증 계층별 처리 가능[web:38][web:39][web:41]

---

## 단점 및 한계

- **성능 저하 가능성**: 계층 간 호출이 많을 경우 불필요한 오버헤드 발생
- **불필요한 복잡성**: 작은 어플리케이션에는 계층 구조가 오히려 복잡도만 증가
- **경직성**: 레이어를 엄격히 지키려다 보면 변화에 대한 대응이 느려질 수 있음[web:38]

---

## 사용 예시

- **일반적인 웹/E-commerce 애플리케이션**  
- **모든 규모의 정보 시스템**
- **ERP, 관리 시스템, 엔터프라이즈 소프트웨어** 등[web:38][web:39][web:41]

## 아키텍처 간 비교: Layered vs. Client-Server

| 항목        | 계층형(Layered)                     | 클라이언트-서버(Client-Server)           |
| ----------- | ------------------------------------| -----------------------------------------|
| 구조        | 계층별 역할 분리, 내부 의존성 최소화 | 클라이언트-서버간 직접 요청-응답         |
| 개발/유지   | 역할 분담이 명확해 관리 수월         | 서버, 클라이언트 각각 독립 개발 용이      |
| 적용 예시   | 웹/앱/ERP 전반                     | 이메일, 온라인 뱅킹, 파일 서버 등         |

---

> 계층형 아키텍처 패턴은 개발·운영·확장의 부담을 줄이고, 표준화된 서비스 구축에 적합한 고전적이면서도 강력한 소프트웨어 설계 방식입니다.
