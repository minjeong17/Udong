# 클라이언트-서버 아키텍처 패턴(Client-Server Architecture Pattern)

## 개요
클라이언트-서버(Client-Server) 아키텍처 패턴은 시스템을 **서비스를 제공하는 서버(Server)**와 **서비스를 요청·소비하는 클라이언트(Client)**, 두 역할로 분리해서 설계하는 대표적인 소프트웨어 구조입니다. 클라이언트는 서버에 요청을 보내고, 서버는 요청을 처리해 결과를 다시 클라이언트에 반환합니다[web:38][web:39][web:41].

---

## 구조

- **서버(Server)**: 다양한 클라이언트에게 서비스(데이터, 연산, 자원 등)를 제공하며 항상 대기
- **클라이언트(Client)**: 서버에 서비스 요청, 결과를 받아 사용
- **통신 프로토콜**: HTTP, TCP/IP, WebSocket 등 네트워크 기반의 다양한 방식 지원


---

## 특징 및 장점

- **확장성**: 서버는 다수의 클라이언트 요청을 동시에 처리
- **중앙 집중**: 자원 및 데이터가 서버에 집중되어 관리·백업 용이
- **보안**: 서버측에서 접근 제어, 인증, 감사 로직을 구현하기 쉬움
- **유지보수 편의**: 서버 소프트웨어만 갱신해도 여러 클라이언트에 즉시 효과 반영
- **다양한 클라이언트 지원**: 하나의 서버에 웹, 모바일, 데스크탑 등 여러 형태의 클라이언트가 연결 가능[web:38][web:39]

---

## 단점 및 한계

- **서버 의존성**: 서버 장애 또는 과부하 발생 시 전체 서비스 영향
- **네트워크 필요**: 오프라인 환경에서는 사용에 제한이 큼
- **단일 장애점(SPOF)**: 서버가 하나일 경우 장애 복원력 부족
- **고가용성 및 로드밸런싱 추가 설계 필요**: 대규모 트래픽, 장애 대응력 확보를 위해 부가구조 필요[web:38][web:39]

---

## 사용 예시

- **웹 애플리케이션**: 브라우저(클라이언트) - 웹서버
- **이메일 시스템**: 이메일 클라이언트 - 메일 서버
- **온라인 뱅킹**: 은행 고객 앱 - 금융 서버
- **파일 서버, 게임 서버, 채팅서버** 등 다양한 인터넷 기반 서비스

---

## 아키텍처 간 비교: 클라이언트-서버 vs. 피어 투 피어

| 항목          | 클라이언트-서버       | 피어 투 피어 (P2P)     |
| --------------| -------------------- | ---------------------- |
| 구조           | 중앙 집중형           | 탈중앙, 모든 노드 계층 없음 |
| 자원관리       | 서버에서 집중        | 각 노드에서 개별 관리   |
| 확장성         | 서버 확장으로 제한적 | 노드 참여로 확장성 우수 |
| 장애영향       | 서버 장애 시 전체 영향| 특정 노드 장애 영향 적음 |
| 보안           | 중앙 집중적으로 관리 | 참가 노드 신뢰성 문제가 있음 |

---

> 클라이언트-서버 아키텍처는 인터넷 시대 핵심 구조로, 오늘날 대다수의 온라인 서비스 및 애플리케이션에 가장 널리 적용되는 기본적인 설계 패턴입니다.
